# Архитектура

Модульный монолит: `backend/app` (FastAPI и CLI используют один конвейер), `frontend` (React, TypeScript, Vite).

| Этап | Исполнитель | Результат |
| --- | --- | --- |
| Разбор | `parser/` | фрагменты с координатами, `text[start:end] == фрагмент` |
| Выделение требований | модель + `analysis/requirements.py` | модель возвращает только ID фрагментов |
| Программные правила | `analysis/rules.py` | замечания без модели |
| Каждое требование | модель, пакеты по 10 | 9 критериев ISO 29148 5.2.5 |
| Набор | модель, два прохода | 5 критериев 5.2.6, расчёт критериев приёмки, попарные противоречия |
| Финтех и безопасность | модель | сценарии событий, возвратов, API |
| Доказательства | `analysis/evidence.py`, `analysis/dedup.py`, модель | поиск цитат, дедупликация, попытка опровержения |
| Исправления | модель | формулировка, критерий приёмки или вопрос аналитику |
| Оценка и отчёт | `analysis/scoring.py`, `reports/` | Score, MD, HTML, JSON |

## Когда замечание подтверждено

Нужно всё сразу: цитата найдена в документе, независимый вызов модели не опроверг замечание, уверенность не ниже 0,75, для противоречия есть два фрагмента. Если проверка не выполнилась, замечание остаётся вопросом. Замечание без найденной цитаты отклоняется. Программные правила подтверждают себя сами, кроме неоднозначных случаев (403 и 404).

Результат критерия у требования согласуется с замечаниями: «нет» ставится только при подтверждённом замечании.

Проверки требований, набора и финтех-сценариев идут параллельно. Программные правила сопоставляются с находками модели, дубли ищет отдельный вызов. Роли моделей и замена при сбое — `llm/router.py`, запросы и общий лимит 20 в минуту — `llm/openrouter.py`.

До анализа проверяется ключ и остаток бесплатных запросов. Если ключ не принят или требования не выделены, анализ останавливается и отчёт не создаётся.

Проверки из веб-интерфейса хранятся в `.data/analyses` (права 0600), удаляются из списка.

## Readiness Score

`S = 0,25·Полнота + 0,20·Однозначность + 0,20·Тестируемость + 0,25·Согласованность + 0,10·Прослеживаемость`

Измерение = `100 − 100·Σштраф / max(N, 10)`, где N — число требований, штраф подтверждённого замечания: critical 10, high 5, medium 2, low 0,5. База прослеживаемости — доля требований с собственным номером в документе. Неоценённые измерения исключаются, покрытие показывается; при покрытии ниже 50% балл не считается. Замечание снижает измерение своей категории и измерения нарушенных критериев. Подтверждённый critical или противоречие high всегда даёт «не готово», открытый вопрос такой серьёзности не даёт «готово»; противоречие двух правил поведения не опускается ниже high. Вопросы critical и high входят в итог. Частичный анализ не даёт «готово». Это методика проекта, не формула ISO.

## Недоверенный ввод

Документ передаётся модели в ограничителях со случайным ID, модель не имеет инструментов и отвечает по схеме. Все тексты в отчётах экранируются. Сервер слушает 127.0.0.1 и проверяет заголовок Host. Ключ остаётся на сервере и не пишется в журнал.
