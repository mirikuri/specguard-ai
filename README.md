# SpecGuard AI

Агент статической проверки требований для финтех-проектов. Читает документ (PDF или Markdown), выделяет требования, проверяет каждое и весь набор по ISO/IEC/IEEE 29148:2018 (5.2.5, 5.2.6) и IEEE 830-1998 (4.3) и формирует отчёт на русском языке. Каждое замечание содержит точную цитату, которую программа нашла в документе.

## Запуск

Нужен Python 3.12+. Для Web UI ещё Node.js 20+.

1. Получите бесплатный ключ: <https://aistudio.google.com/apikey>.
2. Установите агента:
   ```bash
   python -m venv .venv && . .venv/bin/activate
   pip install -e .
   cp .env.example .env      # вставьте ключ в GEMINI_API_KEY
   ```
3. Запустите проверку одной командой:
   ```bash
   python -m app.cli --input docs/requirements.md --output output/report.md
   ```

Отчёт ляжет в `output/report.md`, рядом появятся `report.html` и `report.json`. Вход: `.md` или `.pdf` с текстовым слоем. Проверяемый документ в репозиторий не входит: положите его по любому пути.

Коды выхода: `0` полный отчёт, `2` частичный, `1` ошибка. Без ключа доступен `--rules-only`: только программные правила, отчёт помечается частичным.

### Web UI

```bash
cd frontend && npm ci && npm run build && cd ..
python -m app.main
```
Откройте <http://127.0.0.1:8000>. Если порт занят, задайте `BACKEND_PORT` в `.env`. Для разработки: `npm run dev` в `frontend`, адрес <http://127.0.0.1:5173>.

## Модель

Нужен один ключ Gemini, работа распределена между моделями:

| Роль | Переменная | По умолчанию |
| --- | --- | --- |
| Проверка требований, набора, финтех | `GEMINI_MODEL` | `gemini-3.8-flash` |
| Выделение требований, исправления | `GEMINI_LIGHT_MODEL` | `gemini-3.5-flash-lite` |
| Независимая проверка замечаний | `GEMINI_VALIDATOR_MODEL` | `gemini-3.6-flash` |
| Запасные | `GEMINI_FALLBACK_MODELS` | `gemini-4-hydrogen`, `gemini-3.5-flash`, Gemma 4, `gemini-3.1-flash-lite` |

Если модель исчерпала лимит, не найдена или не отвечает, запрос уходит следующей. Замечания по возможности проверяет модель, которая их не искала. В паспорте указаны модели, реально выполнившие каждый этап. Прогон небольшого документа занимает 9–11 запросов. На бесплатном тарифе у Flash-моделей около 20 запросов в сутки на модель; набор доступных моделей меняется, смотрите AI Studio. Если сильные модели исчерпаны, слабые пропускают больше дефектов: для итогового отчёта запускайте со свежим лимитом.

Текст документа отправляется в Gemini API. Не загружайте конфиденциальные документы на бесплатном тарифе.

## Как это работает

Описание в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Коротко:

- код режет документ на фрагменты с координатами, модель группирует их по ID и не может переписать текст;
- 11 программных правил находят явные дефекты без модели;
- модель проверяет требования пакетами, затем набор, затем финтех-сценарии;
- код ищет каждую цитату в документе, отдельный вызов модели пытается опровергнуть замечание;
- если этап не выполнен, отчёт получает статус «частичный».

## Проверка качества

```bash
pip install -e '.[dev]' && pytest
python -m app.evaluate --dataset                      # 40 дефектов и 8 корректных кейсов
python -m app.evaluate --report output/report.json    # сверка с 18 ожидаемыми дефектами учебного документа
```
`--dataset` выполняет около 8 запросов на каждый из 4 документов. Набор мал, результаты не являются статистически значимой оценкой точности.

## Ограничения

- Результаты Web UI хранятся в памяти и пропадают при перезапуске сервера.
- PDF-сканы без текстового слоя и DOCX не поддерживаются. Координаты в PDF относятся к извлечённому тексту.
- Документы больше 120 тысяч знаков проверяются частями, отчёт помечается частичным.
- Ответы модели могут отличаться между прогонами. Правила, поиск цитат и расчёт оценки детерминированы.
- Это прототип для локального запуска: авторизации нет.
